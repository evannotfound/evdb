## Why

The current system exposes migration inventory and deployment internals instead of providing a simple production database manager. Operators need one concise host configuration and a local command-line tool that can create, inspect, back up, verify, recover, and safely roll back databases over SSH.

## What Changes

- **BREAKING** Replace `host.yml`, `postgres.yml`, and `kv.yml` with one human-owned `host.yml` containing host defaults and concise database entries.
- **BREAKING** Remove migration-only `current`, `target`, repeated image digests, container names, projects, paths, domains, resources, and secret references from each database entry.
- Add a generated lock file for resolved image digests and stable allocated values such as HTTP ports; operators do not edit this file.
- Add a short `evdb` command that runs locally and uses SSH to manage the configured production host.
- Add plan, apply, create, start, stop, restart, status, and log workflows while keeping Ansible as an internal deployment mechanism.
- Add a database details command that shows live metadata, native and HTTP endpoints, and complete usable connection URLs like the existing Montreal manager.
- Manage convention-based database passwords and tokens in 1Password from the local controller without exposing secret values in arguments, config, state, or logs; the details command intentionally reveals requested credentials only in terminal output.
- Present backup creation, backup history, and full restore verification as direct operator workflows.
- Add deployment release history and rollback without changing database data.
- Add staged restore candidates and explicit promotion with automatic recovery to the prior data directory when health checks fail.
- Expand status to cover live engine health, deployment drift, disk space, backup freshness, remote snapshots, and restore-verification freshness.
- Preserve production data and secrets when an instance is stopped, retired, or rolled back; destructive purge remains outside this change.

## Capabilities

### New Capabilities

- `simple-config`: One concise host file, derived database defaults, generated locks, validation, and convention-based secret references.
- `remote-management`: Local SSH control, plan/apply, database creation, routine lifecycle commands, and safe production execution.
- `database-access`: Detailed database inspection, complete connection URLs, HTTP access details, and local 1Password credential resolution.
- `database-observability`: Concise health and drift status for databases, hosts, backups, and recovery checks.
- `backup-operations`: Operator-facing backup creation, history, selection, and full backup verification.
- `release-rollback`: Immutable deployment releases, health-gated activation, automatic failed-apply recovery, and explicit release rollback.
- `restore-promotion`: Isolated restore candidates, verification, explicit promotion, retained prior data, and failed-promotion recovery.

### Modified Capabilities

None. The repository has no archived main capability specs; these capabilities supersede the unshipped migration-oriented interface from `build-db-system`.

## Impact

- Replaces the source configuration model and command syntax in `src/evdb/config.py`, `src/evdb/cli.py`, the checked-in Montreal configuration, tests, and documentation.
- Adds local SSH transport, 1Password item management, desired-versus-deployed planning, Compose lifecycle control, and deployment release manifests.
- Changes Ansible roles and Compose rendering to consume normalized generated configuration rather than three human-authored inventory files.
- Extends existing backup, Restic, status, and isolated restore code instead of replacing their validated data-handling paths.
- Requires a write-capable local 1Password session or service account and SSH/sudo access to the managed host.
- Does not deploy to, restart, or otherwise write to `montreal-01` as part of this change.
